# Slime Assistant — Roblox Above 슬라임 사냥 시제품

Windows에서 Roblox 창을 캡처하고, 등록한 슬라임 이미지와 비슷한 대상을 찾아 방향 조정·접근·공격 입력을 보내는 프로그램입니다. 여러 계정의 작은 창을 순회합니다.

**현재는 실게임에서 검증하지 않은 시제품입니다. 이미지 기반 동작과 모의 Windows 입력 테스트까지 구현했습니다. 검의 실제 사거리, 명중 여부, 처치 여부, 장시간 무인 사냥은 확인하지 않았습니다.**

## 최우선 인수인계: 다른 PC에서 실제 게임으로 확인할 것

**사용자는 이 컴퓨터에서는 게임을 열어 검증할 수 없다고 명시했습니다. 다음 작업자는 사용자가 다른 PC에서 Above를 열어준 뒤, 실제 화면을 관찰하고 검·이동·Z 스킬을 직접 시험해 그 결과로 보정해야 합니다.** 이 단계는 선택적인 추가 확인이 아니라 남아 있는 필수 작업입니다. 문서나 합성 테스트만으로 완료 처리하지 마세요.

- 사용자가 게임에 로그인하고 검을 장착한 뒤 슬라임이 있는 곳에 캐릭터를 세워둡니다. 로그인은 사용자가 직접 합니다.
- 담당 AI는 해당 PC의 화면·입력 도구가 실제 게임을 읽고 조작할 수 있는지 먼저 확인합니다. 입력이 전달되지 않으면 그 제한을 보고하고 작동했다고 주장하지 않습니다.
- 실제 게임에서 검을 휘둘러 공격 방식과 명중 반응을 확인하고, 조금씩 접근하며 맞는 거리와 공격 간격을 보정합니다.
- 여러 거리·각도·밝기에서 슬라임 이미지를 직접 캡처해 기준 이미지를 등록합니다. 사용자가 모든 이미지를 미리 잘라 제공해야 하는 것은 아닙니다.
- 1인칭을 우선 시험하고 실제 시점 회전 방향·감도·전진량을 관찰합니다. 1인칭 권장은 현 구조에 대한 판단일 뿐, 실측으로 최적 시점을 확정한 결과가 아닙니다.
- Z 스킬은 사용자가 **쿨타임 5초**라고 알려줬습니다. 이는 사용자 제공 정보이며 아직 실측하지 않았습니다. 실제 발동, 범위, 쿨타임 표시, 일반 검 공격과의 간섭을 확인한 뒤 자동 사용을 구현·보정합니다.
- **현재 코드에는 Z 자동 사용 기능이 없습니다.** 앞선 대화에서 추가 방향을 설명하고 코드 확인만 했으며, 사용자가 실제 게임이 열린 상태를 기준으로 하라고 하여 구현/실측을 보류했습니다.
- 나무·가림·여러 슬라임·바뀌는 환경이 실제 요구입니다. 평지나 고정된 환경만 가정해 전체 요구를 충족했다고 보고하지 마세요. 현재 장애물 우회는 미구현입니다.

이 PC의 경로를 다른 컴퓨터에 그대로 적용하지 마세요. 다음 PC에서는 이 저장소를 clone한 실제 프로젝트 루트에서 작업합니다. 아래에 나오는 `C:\Users\mylink\...`는 현재 PC의 기록입니다.

## 다음 AI가 먼저 알아야 할 사용자 요구

최근 갱신: 2026-11-27.

- 대상 게임은 Roblox **Above**, 사냥 대상은 **슬라임만**입니다.
- 주로 사용할 무기는 **검**입니다. 지팡이 분석도 질문했으나, 최신 답변에서 검을 선택했습니다.
- 검의 **Z 스킬 자동 사용**을 추가 요청했습니다. 쿨타임은 사용자 제공값 **5초**, 자동 사용 구현·발동 검증은 아직 보류 상태입니다.
- 작은 게임 창을 여러 개 띄워 여러 계정을 운영하려고 합니다.
- 최신 요구는 **현재 보이는 슬라임을 따라가기**입니다. 특정 A의 신원을 죽을 때까지 유지하는 요구를 단순화했습니다. 후보 중 조준점에 가까운 대상을 매 관측에서 선택합니다.
- 현재 제어 방식에는 **1인칭을 우선 권장**하며 프로그램 기본값도 1인칭입니다. 게임 안의 시점은 직접 맞춰야 합니다. 3인칭 우클릭 회전 설정도 제공합니다. 어느 모드든 실제 Roblox 조작은 미검증입니다.
- 사용자는 게임 모더에게 이미지 분석 기반 자동 사냥 허락을 받았다고 명시했습니다. 이미 받은 허락을 다시 확인해 달라고 요구하지 마세요.
- 가림이나 일시 오류로 쉽게 종료되지 않고 자동 복구되길 원합니다.
- 사용자는 **이 컴퓨터에서 게임을 열 수 없습니다.** 다른 PC에서 게임을 열어준 뒤 실제 화면과 조작 결과를 기준으로 분석·보정하는 것을 명시적으로 요청했습니다.
- 실제 플레이를 확인하지 않고 사거리 측정·검 공격 실험·사냥 성공을 했다고 말하면 안 됩니다.
- 사용자가 앞서 준 스크린샷은 숲과 가림이 많은 게임 화면의 예시입니다. 해당 이미지로 탐지 모델을 학습하거나 검 사거리를 측정하지 않았습니다. 기준 슬라임 이미지는 이 저장소에 제공되지 않았습니다.

### 현재 사냥 판단의 정확한 의미

`engine.py`의 `action_for()`는 다음 순서로 판단합니다.

1. 현재 화면에서 조준점에 가까운 슬라임을 고르고, 라벨·위치가 비슷한 후보가 3프레임 이상 확인돼야 조작합니다. 사냥 모드에서는 짧은 추가 관측으로 확인 횟수를 채웁니다.
2. 표적 중심과 화면 중심의 차이가 가로 7%, 세로 12%를 넘으면 시점을 조정합니다.
3. 중심에 정렬돼 있고 `표적 박스 높이 / 화면 높이 < near_ratio`이면 약 0.1초간 전진합니다.
4. 비율이 기준 이상이고 공격 간격이 지났으면 클릭합니다.
5. 입력 직전 창을 활성화하고 화면을 다시 읽습니다. 새 화면에서 표적을 잃으면 오래된 좌표로 전진하지 않습니다.

기본 `near_ratio=0.16`, `attack_interval=0.65`, `camera_gain=0.20`은 **임시 설정값**입니다. 게임에서 측정한 수치가 아니며 거리 단위(studs/미터)로 해석하면 안 됩니다. 같은 슬라임도 카메라 배율과 창 크기에 따라 보이는 크기가 달라집니다.

가림은 인식 영역의 25개 지점에서 최상위 창을 확인하는 방식입니다. 지점 사이의 작은 가림까지 보장하지 않습니다. 캡처는 데스크톱 픽셀을 읽으므로 완전히 가려진 게임 화면을 그대로 읽는 기능은 없습니다.

자동 복구가 켜진 사냥 모드는 필요 시 게임 창을 다시 활성화합니다. 다른 PC 작업과 함께 사용하기 어렵고, 사용자가 직접 PC를 쓰려면 F9로 먼저 정지해야 합니다. F9 정지는 자동 재개하지 않습니다.

### 여러 슬라임이 탐지될 때 현재 동작

- 탐지기는 여러 후보 박스를 반환하고 중복을 제거하며 최대 20개까지 전달합니다. 템플릿·배율마다 후보 수 제한도 있어 화면의 모든 몹을 찾는다고 보장하지 않습니다.
- `Tracker`는 매 관측마다 **현재 화면 중심에 가까운 후보**를 유사도와 함께 평가해 한 마리를 선택합니다. 이전 표적이 새로 나타난 중앙 후보를 계속 제치지 않습니다.
- 이전 후보와 라벨이 같고 위치 차이가 일정 범위 이내이면 연속 확인 횟수를 늘립니다.
- 다수 후보를 서로 다른 ID로 끝까지 추적하는 구조는 아닙니다. 여러 개가 교차하거나 가려지면 표적이 바뀔 수 있습니다.
- 시점 조정/전진 후에는 확인 이력을 무조건 reset하지 않습니다. 새 화면의 후보가 라벨·위치 기준에 맞는지 다시 판단합니다. 표적 상실·큰 위치 변화·오류·회전 탐색·오래된 관측에서는 확인을 초기화합니다.
- 특정 A를 죽을 때까지 고정하는 기능은 없습니다. 현재 사용자가 수용한 방식은 **보이는 대상을 따라가며, 필요하면 다른 후보로 전환**하는 것입니다.
- 후보가 사라지는 것은 화면에서 놓쳤다는 뜻일 수 있습니다. 처치로 판정하지 않습니다. 표시 횟수도 처치 수가 아닌 공격 입력 횟수입니다.

## 아직 하지 않은 것

- 실제 게임을 켜서 검을 휘두르거나 지팡이를 발사한 실험.
- 검의 실제 명중 거리·공격 주기·타격 방향·공격 후딜 측정.
- Z 키 자동 사용, 계정별 쿨타임 관리, Z의 실제 발동·범위·쿨타임·공격 간섭 확인. 5초라는 정보만 사용자에게 받았습니다.
- 몹 체력 감소·피격 이펙트·처치 확인.
- 카메라 이동 부호·감도, Roblox에서 `SendInput` 입력이 정상 반영되는지 확인.
- 여러 슬라임의 교차·가림 상황에서 현재 후보 선택이 실제로 안정적인지 검증. 영구 ID나 처치 확인은 구현하지 않았습니다.
- 슬라임 기준 이미지 수집, 학습 모델 훈련, 실제 인식 정확도 평가.
- 장애물 우회, 낭떠러지 회피, 막힘 감지/복구, HP 관리, 부활, 재접속.
- 여러 계정의 실제 장시간 연속 운영·자원 사용량 측정.

현재 게임 창은 열려 있지 않았고, 사용자가 열 수 없다고 명확히 말했습니다. 이번 인수인계 시점까지 실제 게임 테스트는 하지 않았습니다.

### 게임 화면 없이 가능한 작업

1. 이 README와 `AGENTS.md`, `vision.py`, `engine.py`, 기존 테스트를 먼저 읽습니다.
2. 최신의 “보이는 대상 따라가기” 요구를 유지합니다. 다중 후보가 교차하거나 비슷한 위치에 있을 때 선택이 불필요하게 흔들리는지 검증합니다. A의 처치 확인을 다시 필수 조건으로 만들지 않습니다.

4. 검용 프로필에서 화면 기준 접근 거리와 공격 주기를 조정할 수 있게 하되, 기본값과 실측값을 구분해 저장합니다.
5. 합성 시퀀스로 여러 몹 교차, 유사한 두 몹, 짧은 가림, 표적 상실, 계정별 상태 분리를 테스트합니다.
6. 실제 명중 데이터를 받기 전까지 “검 사거리 자동 분석 완료” 같은 상태를 만들지 않습니다.

### 다른 PC에서 사용자가 게임을 열어주면 반드시 할 작업

1. 검을 장착한 한 계정부터 시작합니다. 실제 게임/장착 무기/카메라 상태를 확인합니다.
2. 담당 AI가 직접 화면을 캡처해 사용할 작은 창 크기와 카메라 배율에서 슬라임 기준 사진을 모읍니다. 수집 때의 시점·화면 크기·거리 구분을 기록합니다.
3. 이동과 공격 전후의 화면을 비교하면서, 시점 이동 방향·W 접근·공격 반응을 각각 확인합니다.
4. 거리별로 공격했을 때 몹 체력 감소 등 신뢰할 수 있는 피격 증거가 있는지 관찰합니다. 클릭 성공이나 공격 애니메이션만으로 명중을 단정하지 않습니다.
5. 관측한 카메라 설정과 슬라임 종류에 대해 검용 거리 기준·공격 간격을 보정하고 근거를 기록합니다.
6. **Z 스킬을 실제로 눌러** 발동 조건·공격 범위·사용자 제공 쿨타임 5초·일반 공격과의 간섭을 확인합니다. 키 입력 시도와 실제 스킬 발동을 구분합니다.
7. 확인 결과에 맞춰 계정별 마지막 사용 시각을 분리한 Z 자동 사용을 구현합니다. 사냥 모드/적 확인/입력 가능한 창/F9 정지 조건을 유지하고, 스킬 때문에 검 공격이 계속 취소되거나 키가 눌린 채 남지 않게 합니다. 쿨타임 표시를 읽는 방식과 5초 타이머 방식 중 실제 화면에서 가능한 것을 선택하고 차이를 명시합니다.
8. 한 계정의 보이는 슬라임 따라가기 → 여러 슬라임 → 나무·가림·막힘 상황 → 여러 계정 순서로 확장합니다. 불가능하거나 실패하는 경우도 기록합니다. 장시간 테스트 없이 무중단을 보장하지 않습니다.
9. 실제 관측값과 수정 사항, 실패 사례를 README/사용법 및 관련 테스트에 반영합니다. 게임을 열 수 없거나 도구 입력이 먹히지 않으면 이 단계는 미완료로 남깁니다.

최소 기록 항목:

| 항목 | 기록할 근거 |
|---|---|
| 게임·무기·시점·창 크기 | 실제 확인한 게임/검 종류/1인칭 또는 3인칭/클라이언트 해상도 |
| 검 명중 거리 | 접근 전후의 화면과 체력 감소 등 피격 증거, 적용한 화면 비율 |
| 시점·전진 | 입력 방향/크기/시간에 따른 실제 변화와 채택한 설정 |
| 슬라임 이미지 | AI가 캡처한 색·각도·거리·조명 구분, 실제 탐지 실패 사례 |
| Z 스킬 | 사용자 제공 5초와 실제 관측값의 구분, 발동 증거, 자동 사용 방식, 계정별 관리 |
| 다계정·가림·장애물 | 실제로 시험한 계정 수/상황/기간/실패와 미검증 범위 |

사용자는 AI가 게임을 직접 조작해 분석하고 이미지를 수집하는 작업을 요청했습니다. **이 컴퓨터에서 실행할 수 없어서 다른 PC의 실제 게임 화면을 기다리는 상태**입니다. 화면이 준비되면 위 실측 작업을 진행하고, 그 전에는 임의로 로그인하거나 없는 관측값을 만들어서는 안 됩니다.

## 실행과 빌드

Windows 10/11 64비트, Python 3.13 기준입니다. Tkinter가 포함된 Python이 필요합니다.

```powershell
cd C:\Users\mylink\orca\projects\ropx_-macro
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe run.py
```

테스트는 실제 마우스/키 입력을 보내지 않습니다.

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

빌드는 의존성 설치 → 테스트 → PyInstaller → ZIP 생성 순서입니다.

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\build.ps1
```

출력:

```text
dist-visible-follow/SlimeAssistant/SlimeAssistant.exe
dist-visible-follow/SlimeAssistant-VisibleFollow.zip
```

실행 파일은 `_internal` 등 같은 폴더 전체가 필요합니다. ZIP을 전부 풀어 실행하세요. 빌드 결과와 `.venv`는 Git에 넣지 않습니다. 최신 빌드는 현재 PC의 새 프로젝트에 복사돼 있지만, clone만 한 환경에서는 직접 빌드해야 합니다.

새 프로젝트로 옮긴 뒤 테스트 20개가 통과했습니다. 당시에는 이전 작업 폴더에 설치된 `.venv`의 Python으로 새 프로젝트의 테스트를 실행했습니다. 새 프로젝트의 `.venv`는 아직 만들지 않았으므로 위 명령으로 준비하세요.

## 테스트 결과의 범위

최근 결과: **23개 통과**. 테스트는 `tests/test_assistant.py`에 있습니다.

- 합성 이미지의 위치·배율·ROI 제외, 무관한 배경 및 단색 기준 거부.
- 표적 상실 시 연속 확인 초기화.
- 비활성 창에 입력하지 않음, 전진/시점 오류 후 키·버튼 해제.
- 감지 전용에서 계정 창을 활성화하지 않음.
- 두 계정의 모의 공격과 횟수 분리.
- 가림 복구 후 재확인, 자동 복구를 끈 경우 가린 계정 보류.
- 일시 캡처 오류 때 다른 계정 처리 지속.
- 표적 상실 시 이전 좌표로 전진하지 않음.
- 방향 조정 → 접근 → 공격의 조건 분기.
- F9 정지, 복구 해제 시 포커스 변경 정지, 창 배치 계산.
- 현재 중앙 후보 우선 선택, 표적 라벨 변경 시 재확인, 1인칭 기본값(우클릭 비활성).

**Windows 창·화면 캡처·입력은 대부분 mock입니다.** 실제 Roblox 창 제어, 검 명중, 실제 거리, 장시간 사냥 성공을 검증한 테스트가 아닙니다. 초기에 첫 버전 GUI가 실행되는 것은 확인했지만, 최신 추적·복구 버전의 실게임 연동 확인으로 해석하면 안 됩니다.

데이터 저장 위치는 `%LOCALAPPDATA%\SlimeAssistant`입니다. `templates/`, `archived-templates/`, `settings.json`, `activity.log` 등이 저장되며 모든 버전이 이 경로를 공유합니다. 시작 모드와 창 핸들은 자동 재사용하지 않습니다.

개인 기준 이미지·로컬 설정·로그는 저장소에 포함하지 않았습니다. 이전 GUI의 `실행화면.png`도 현재 버전/게임 동작의 증거가 아니므로 커밋 대상에서 제외합니다.
