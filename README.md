# Slime Assistant — Roblox Above 슬라임 사냥 시제품

Windows에서 Roblox 창을 캡처하고, 등록한 슬라임 이미지와 비슷한 대상을 찾아 방향 조정·접근·공격 입력을 보내는 프로그램입니다. 여러 계정의 작은 창을 순회합니다.

**현재는 실게임에서 검증하지 않은 시제품입니다. 이미지 기반 동작과 모의 Windows 입력 테스트까지 구현했습니다. 검의 실제 사거리, 명중 여부, 처치 여부, 장시간 무인 사냥은 확인하지 않았습니다.**

## 다음 AI가 먼저 알아야 할 사용자 요구

인수인계 기준: 2026-11-26.

- 대상 게임은 Roblox **Above**, 사냥 대상은 **슬라임만**입니다.
- 주로 사용할 무기는 **검**입니다. 지팡이 분석도 질문했으나, 최신 답변에서 검을 선택했습니다.
- 작은 게임 창을 여러 개 띄워 여러 계정을 운영하려고 합니다.
- 몹이 보이면 그 몹에게 접근해서 잡고, 여러 몹이 있으면 표적을 골라 순서대로 처리하길 원합니다.
- 사용자는 게임 모더에게 이미지 분석 기반 자동 사냥 허락을 받았다고 명시했습니다. 이미 받은 허락을 다시 확인해 달라고 요구하지 마세요.
- 가림이나 일시 오류로 쉽게 종료되지 않고 자동 복구되길 원합니다.
- 사용자는 **지금 게임 화면을 열 수 없습니다.** 최신 요청은 진행 상태를 자세히 기록하고 다음 AI가 이어받도록 README를 작성해 **커밋**하는 것입니다.
- 실제 플레이를 확인하지 않고 사거리 측정·검 공격 실험·사냥 성공을 했다고 말하면 안 됩니다.
- 사용자가 앞서 준 스크린샷은 숲과 가림이 많은 게임 화면의 예시입니다. 해당 이미지로 탐지 모델을 학습하거나 검 사거리를 측정하지 않았습니다. 기준 슬라임 이미지는 이 저장소에 제공되지 않았습니다.

### 현재 사냥 판단의 정확한 의미

`engine.py`의 `action_for()`는 다음 순서로 판단합니다.

1. 동일하다고 판단한 표적을 3프레임 이상 확인합니다. 사냥 모드에서는 짧은 추가 관측으로 확인 횟수를 채웁니다.
2. 표적 중심과 화면 중심의 차이가 가로 7%, 세로 12%를 넘으면 시점을 조정합니다.
3. 중심에 정렬돼 있고 `표적 박스 높이 / 화면 높이 < near_ratio`이면 약 0.1초간 전진합니다.
4. 비율이 기준 이상이고 공격 간격이 지났으면 클릭합니다.
5. 입력 직전 창을 활성화하고 화면을 다시 읽습니다. 새 화면에서 표적을 잃으면 오래된 좌표로 전진하지 않습니다.

기본 `near_ratio=0.16`, `attack_interval=0.65`, `camera_gain=0.20`은 **임시 설정값**입니다. 게임에서 측정한 수치가 아니며 거리 단위(studs/미터)로 해석하면 안 됩니다. 같은 슬라임도 카메라 배율과 창 크기에 따라 보이는 크기가 달라집니다.

가림은 인식 영역의 25개 지점에서 최상위 창을 확인하는 방식입니다. 지점 사이의 작은 가림까지 보장하지 않습니다. 캡처는 데스크톱 픽셀을 읽으므로 완전히 가려진 게임 화면을 그대로 읽는 기능은 없습니다.

자동 복구가 켜진 사냥 모드는 필요 시 게임 창을 다시 활성화합니다. 다른 PC 작업과 함께 사용하기 어렵고, 사용자가 직접 PC를 쓰려면 F9로 먼저 정지해야 합니다. F9 정지는 자동 재개하지 않습니다.

### 여러 슬라임이 탐지될 때 현재 동작

- 탐지기는 여러 후보 박스를 반환하고 중복을 제거하며 최대 20개까지 전달합니다. 템플릿·배율마다 후보 수 제한도 있어 화면의 모든 몹을 찾는다고 보장하지 않습니다.
- `Tracker`는 **이전 표적 중심에 가까운 후보**, 처음에는 **화면 중심에 가까운 후보**를 유사도와 함께 평가해 한 마리를 선택합니다.
- 이전 후보와 라벨이 같고 위치 차이가 일정 범위 이내이면 연속 확인 횟수를 늘립니다.
- 다수 후보를 서로 다른 ID로 끝까지 추적하는 구조는 아닙니다. 여러 개가 교차하거나 가려지면 표적이 바뀔 수 있습니다.
- 특히 **시점 조정/전진 후 추적기를 reset**하므로 다음 관측에서 다른 표적으로 갈아탈 수 있습니다.
- 따라서 “선택한 한 마리를 안정적으로 끝까지 따라가서 잡고 다음 몹으로 이동”은 **아직 완성되지 않았습니다.** 사용자 최신 요구이며 다음 작업의 핵심입니다.
- 후보가 사라지는 것은 화면에서 놓쳤다는 뜻일 수 있습니다. 처치로 판정하지 않습니다. 표시 횟수도 처치 수가 아닌 공격 입력 횟수입니다.

## 아직 하지 않은 것

- 실제 게임을 켜서 검을 휘두르거나 지팡이를 발사한 실험.
- 검의 실제 명중 거리·공격 주기·타격 방향·공격 후딜 측정.
- 몹 체력 감소·피격 이펙트·처치 확인.
- 카메라 이동 부호·감도, Roblox에서 `SendInput` 입력이 정상 반영되는지 확인.
- 여러 슬라임에 대한 안정적인 표적 고정과 표적 전환 정책.
- 슬라임 기준 이미지 수집, 학습 모델 훈련, 실제 인식 정확도 평가.
- 장애물 우회, 낭떠러지 회피, 막힘 감지/복구, HP 관리, 부활, 재접속.
- 여러 계정의 실제 장시간 연속 운영·자원 사용량 측정.

현재 게임 창은 열려 있지 않았고, 사용자가 열 수 없다고 명확히 말했습니다. 이번 인수인계 시점까지 실제 게임 테스트는 하지 않았습니다.

## 다음 AI의 작업 순서

### 게임 화면 없이 가능한 작업

1. 이 README와 `AGENTS.md`, `vision.py`, `engine.py`, 기존 테스트를 먼저 읽습니다.
2. 여러 몹에 대한 표적 선택/유지 구조부터 개선합니다. 한 마리 선택 → 위치/크기 연관 추적 → 짧은 가림에서 유지 → 타임아웃 후 재선택을 명시적인 상태로 다루는 것이 필요합니다.
3. 시점 조정·전진 때마다 표적 정보가 사라지는 문제를 해결하되, 오래된 좌표로 입력하는 방식으로 바꾸지 않습니다. 재관측과 표적 유지 상태를 분리하는 방향을 검토합니다.
4. 검용 프로필에서 화면 기준 접근 거리와 공격 주기를 조정할 수 있게 하되, 기본값과 실측값을 구분해 저장합니다.
5. 합성 시퀀스로 여러 몹 교차, 유사한 두 몹, 짧은 가림, 표적 상실, 계정별 상태 분리를 테스트합니다.
6. 실제 명중 데이터를 받기 전까지 “검 사거리 자동 분석 완료” 같은 상태를 만들지 않습니다.

### 사용자가 나중에 게임을 열 수 있을 때

1. 검을 장착한 한 계정부터 시작합니다. 실제 게임/장착 무기/카메라 상태를 확인합니다.
2. 사용할 작은 창 크기와 카메라 배율을 고정하고 슬라임 기준 사진을 모읍니다.
3. 이동과 공격 전후의 화면을 비교하면서, 시점 이동 방향·W 접근·공격 반응을 각각 확인합니다.
4. 거리별로 공격했을 때 몹 체력 감소 등 신뢰할 수 있는 피격 증거가 있는지 관찰합니다. 클릭 성공이나 공격 애니메이션만으로 명중을 단정하지 않습니다.
5. 관측한 카메라 설정과 슬라임 종류에 대해 검용 거리 기준·공격 간격을 보정하고 근거를 기록합니다.
6. 한 마리 추적 → 여러 슬라임 → 여러 계정 순서로 확장합니다. 장시간 테스트 없이 무중단을 보장하지 않습니다.

사용자는 게임을 직접 조작해 분석하는 것에 관심과 의사를 밝혔지만 **현재 화면을 제공할 수 없습니다.** 지금 해야 할 일은 이 상태를 보존하는 것이며, 임의로 로그인하거나 없는 실측 결과를 만들어서는 안 됩니다.

## 실행과 빌드

Windows 10/11 64비트, Python 3.13 기준입니다. Tkinter가 포함된 Python이 필요합니다.

```powershell
cd C:\Users\mylink\orca\projects\ropx_-macro
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe run.py
```

테스트는 실제 마우스/키 입력을 보내지 않습니다.

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

빌드는 의존성 설치 → 테스트 → PyInstaller → ZIP 생성 순서입니다.

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\build.ps1
```

출력:

```text
dist-auto-chase/SlimeAssistant/SlimeAssistant.exe
dist-auto-chase/SlimeAssistant-AutoChase.zip
```

실행 파일은 `_internal` 등 같은 폴더 전체가 필요합니다. ZIP을 전부 풀어 실행하세요. 빌드 결과와 `.venv`는 Git에 넣지 않습니다. 최신 빌드는 현재 PC의 새 프로젝트에 복사돼 있지만, clone만 한 환경에서는 직접 빌드해야 합니다.

새 프로젝트로 옮긴 뒤 테스트 20개가 통과했습니다. 당시에는 이전 작업 폴더에 설치된 `.venv`의 Python으로 새 프로젝트의 테스트를 실행했습니다. 새 프로젝트의 `.venv`는 아직 만들지 않았으므로 위 명령으로 준비하세요.

## 테스트 결과의 범위

최근 결과: **20개 통과**. 테스트는 `tests/test_assistant.py`에 있습니다.

- 합성 이미지의 위치·배율·ROI 제외, 무관한 배경 및 단색 기준 거부.
- 표적 상실 시 연속 확인 초기화.
- 비활성 창에 입력하지 않음, 전진/시점 오류 후 키·버튼 해제.
- 감지 전용에서 계정 창을 활성화하지 않음.
- 두 계정의 모의 공격과 횟수 분리.
- 가림 복구 후 재확인, 자동 복구를 끈 경우 가린 계정 보류.
- 일시 캡처 오류 때 다른 계정 처리 지속.
- 표적 상실 시 이전 좌표로 전진하지 않음.
- 방향 조정 → 접근 → 공격의 조건 분기.
- F9 정지, 복구 해제 시 포커스 변경 정지, 창 배치 계산.

**Windows 창·화면 캡처·입력은 대부분 mock입니다.** 실제 Roblox 창 제어, 검 명중, 실제 거리, 장시간 사냥 성공을 검증한 테스트가 아닙니다. 초기에 첫 버전 GUI가 실행되는 것은 확인했지만, 최신 추적·복구 버전의 실게임 연동 확인으로 해석하면 안 됩니다.

| `run.py` | GUI 실행 진입점 |
| `slime_assistant/app.py` | Tkinter UI, 창/기준 선택, 설정, 핫키, 상태 표시 |
| `slime_assistant/windows.py` | 창 조회·배치·가림 샘플 검사, 전경 확인, 일반 OS 입력 |
| `slime_assistant/vision.py` | 기준 이미지, 다중 배율 탐지, 추적기, 미리보기 |
| `slime_assistant/engine.py` | 계정별 관측·복구·시점·접근·공격 판단 |
| `tests/test_assistant.py` | 합성/모의 테스트 20개 |
| `requirements.txt` | 실행 의존성 |
| `build.ps1` | 테스트 및 Windows 배포 빌드 |
| `사용법.txt` | 현재 사용자용 조작 설명 |
| `AGENTS.md` | 다음 AI를 위한 짧은 작업 지침 |

데이터 저장 위치는 `%LOCALAPPDATA%\SlimeAssistant`입니다. `templates/`, `archived-templates/`, `settings.json`, `activity.log` 등이 저장되며 모든 버전이 이 경로를 공유합니다. 시작 모드와 창 핸들은 자동 재사용하지 않습니다.

개인 기준 이미지·로컬 설정·로그는 저장소에 포함하지 않았습니다. 이전 GUI의 `실행화면.png`도 현재 버전/게임 동작의 증거가 아니므로 커밋 대상에서 제외합니다.
